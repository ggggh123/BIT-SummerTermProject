## 本轮结果

### 结算提示一闪而过

排查时对用户正在使用的运行库进行了只读查询：订单 #432 应付 165 分，已停止、未结算，其所属账号余额为 0 分。这种情况下服务端拒绝结算是正确行为，不应绕过余额检查。

客户端缺陷在于：收到 `INSUFFICIENT_BALANCE` 后发起只读核验；`order.current` 和 `station.detail` 成功时会把失败提示清除，导致界面停留原处却没有原因说明。

本轮修改：

- 相同订单仍处于原状态时，保留业务失败提示；只读核验成功不等于结算成功。
- 明确显示「余额不足，请充值后再结算」，并提供「前往账户充值」。
- 核验期间继续禁用写操作；核验完成后允许用户主动重试，不自动重发扣款。
- 重试、成功结算、切换订单或退出登录时清理旧提示，避免污染其他订单。
- 充值输入错误或结果待确认时，也在账户余额卡片内显示提示，避免新增统计区把反馈挤到页面底部。

未替用户充值、结算、取消订单或修改活动轮次数据库。

### 历史订单卡片

去掉整个列表获取焦点时的青绿外框，改为单选订单卡片描边与背景变化。鼠标选择、键盘上下切换均有明确的单卡反馈；仍是只读订单展示，不声称点击后打开详情。长站名、长充电桩编号、分页、离线缓存与既有排序保留。

### 我的账户

新增「我的用电足迹」：累计用电、本月用电、已结算费用、充电次数、累计时长、已结算次数、待结算金额提示，以及近七天柱状图。补充账号 ID 与注册日期。

数据通过新只读接口 `user.statistics` 从当前账号的全部订单计算，不从当前页历史记录估算，不在正式程序中植入示例统计。七日／本月电量按订单开始日期（北京时间）归集，包含进行中已充电量；已结算费用不含待结算金额。空账号显示真实 0，未加载和读取失败显示单独状态。

账号管理位于右上角：

- 「切换账号」「退出当前账号」均先确认，默认选择留在当前账号。
- 确认后返回登录页、清空手机号输入、账户数据、订单与地图状态；旧会话返回的数据不能刷新新账号。
- 退出只结束本机登录，不是服务端全设备 token 撤销，不会停止充电或处理未结算订单。
- 正在提交的充值／订单操作或待核验结果，不能用退出账号跳过处理。

### 地图与登录页

- 驾车／步行改为两个互斥按钮，支持直接点击与键盘操作；保留异步请求隔离、失败重试、上次成功路线提示。地图自身的加载背景和路线信息浮层也使用深色配色。
- 登录插画改为深蓝背景、青绿灯光的车辆和充电桩，旧白绿色资源保留。生成方式为内置 ImageGen；[新资源](../../../apps/user-client/resources/ui/login-pulse.png)及[完整提示词记录](../../../apps/user-client/resources/ui/login-pulse-prompt.md)已保存，程序通过 Qt 资源系统嵌入新图。

接口完整字段和兼容说明见 [接口合同第 29 项](../interface-contract.md)。旧 `user.get` 字段结构未变，无数据库迁移；旧服务端不支持统计时，客户端统计区会明确提示，不阻断资料和充值功能。

## 验证与边界

- 本机 Ubuntu 25.04、Qt 6.8.3、Release/Ninja 构建；保持 Ubuntu 22.04 / Qt 6.2 源码基线，但本轮没有在 Ubuntu 22.04 系统重新运行，也没有下载镜像或安装新环境。
- CTest 全部 36 组通过，分两批执行：先运行客户端会话、结算、历史订单、手机布局、地图切换与重试、真实 TCP 服务端业务、UTC／北京时间统计、核心联调和运行工具等 35 组（39.54 秒），日志：[ctest-local.log](ctest-local.log)。
- `demo_runtime_live` 整轮启停检查首次被 `ACTIVE_SERVER` 正确阻止，因为用户已有活动轮次，未绕过保护或停止用户程序。之后只读检查确认原三端进程均已退出，再补跑剩余 1 组（8.42 秒）：真实三程序启停与连接检查、错误模拟器 token 的失败回收均通过。测试只创建和停止自身新轮次，日志：[ctest-live.log](ctest-live.log)。
- 本机新版启动包装层 14 项自动测试通过。
- 本轮独立启停证据：`runtime/demo-runs/live-20260908-191530-14369f6d`（正常三端）和 `runtime/demo-runs/live-20260908-191537-9a352d58`（错误 token 回收）；两轮最终均为 `STOPPED`，测试进程均为 `EXITED`，黄金库 SHA-256 未改变。
- 地图控制与异步切换验证使用离线替身，不调用真实腾讯 API、不消耗地图调用额度；不能据此声称本轮已完成在线导航验证。
- 本页截图来自真实 Qt 控件的离屏渲染，不是设计稿；截图中的数字使用确定性回归测试数据，正式程序仍读取服务端实际订单。

额外修复：编译后旧程序的 `/proc/PID/exe` 会带 ` (deleted)` 后缀，之前一键工具会误报 `WRONG_PID`。现在仅接受这一精确后缀，同时继续核验 PID、启动时刻、boot ID 和完整路径；用真实临时测试进程验证了重新链接后的正常停止及拒绝错误身份。用户当前三个进程只检查状态，没有发送停止信号。
