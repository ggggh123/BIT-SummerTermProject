## 实际数据的边界

新增 `order.telemetry` 是独立的只读扩展，详见上级 `interface-contract.md` 第 28 项。客户端与服务端应同步升级；旧客户端仍可连新服务端，旧服务端不会返回新曲线。

1. 用户端以订单开始/结束时间映射现有遥测记录，最多 600 条。固定周期的权威订单读取完成后，再进行曲线查询；隐藏、断线或操作未确认时不重复读取。
2. 游标只影响采样读数；订单总电量与金额仍以服务端订单为准。管理端“窗口积分电量 / 非账单”只用于分析，不用于扣款。
3. 两个有效样本间可线性回看；间隔超过 120 秒视为缺口，不连线。末点外超过 15 秒无读数；旧数据明确标记历史采样。
4. 数据未到达或无样本时显示等待/“—”，接口失败有明确提示，不回退到测试样本。
5. 管理端只显示选中设备与另一台有采样设备的对照，合计不冒充全站功率。窗口最多 30 分钟、每设备最多 600 点；窗口滚动时保持已选的绝对回看时刻，超出保留范围才钳制到边界。

## 重现构建与截图

团队在独立 clone 使用既有 `ubuntu22-test` 预设构建。以下是本机本轮实际构建目录，不是全局安装目录：

```bash
cmake -S /mnt/hgfs/Desktop/SummerTermProject/worktrees/energy-pulse-ui \
  -B /home/hushengyuan/ev-release/build-energy-pulse -G Ninja \
  -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build /home/hushengyuan/ev-release/build-energy-pulse --parallel 4
ctest --test-dir /home/hushengyuan/ev-release/build-energy-pulse --output-on-failure --parallel 4
```

设置 `QT_QPA_PLATFORM=offscreen`，再分别设置 `EV_UI_SCREENSHOT_DIR` / `EV_ADMIN_UI_CAPTURE_DIR` 到需要留档的目录，运行 `tst_user_mobileui` / `tst_admin_ui`；前者的 `pulseSamplingAndCursorPreserveAuthoritativeActions` 与后者的 `energySamplesAndDeviceSelectionStayLinked` 生成本轮对照图。

本轮没有重写需求矩阵，也没有改动腾讯地图密钥或其在线业务路径。需要展示本轮界面时应运行新工作树对应构建；旧的一键入口与既有发行包不会自动切换。
