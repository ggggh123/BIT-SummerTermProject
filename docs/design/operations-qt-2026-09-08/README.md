## 数据与操作边界

1. 新增内部只读 `AdminView::Operations`，由 DB worker 查询站点、设备及最后一条入库遥测；仍校验管理员身份，不新增公开 TCP action，不改变 Schema。
2. 站点按数据库 ID 而非名称分组，两个重名站点不会合并。筛选后不可见的设备取消选择；刷新保持仍有效的设备 ID。
3. 设备额定功率、累计次数、累计时长来自数据库；额定功率不是瞬时充电功率。该页不补预设样本、不生成状态。
4. 只有快照可用、选中故障桩且没有在途控制时，重启按钮才可用。确认默认“取消”；业务仍走 `admin.charger_restart`，先收到回包，再等待数据库中的 `restarting → idle`。取消不写重启审计，重复点击不多发请求。
5. 读取失败保留旧快照供参考并明确标记，停止设备操作；不会把错误转换成“0 台故障”或“所有服务正常”。
6. 健康页显示真实监听状态、读取结果以及是否存在已入库遥测。遥测时刻是设备记录时间，不是进程心跳或服务端接收时刻；“已有记录”不等于模拟器当前在线。
7. 没有 CPU／内存／在线心跳观测就不显示这些指标。保留预测扩展诊断，但明确其不参与核心验收。
8. 黄金数据复位保持原二次确认、单次在途控制和失败回执重试使用同一 requestId 的约束。布局调整不放宽写入权限。
