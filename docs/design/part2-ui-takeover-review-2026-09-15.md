## 4. 最新上游变化对 UI 的直接影响

### 4.1 数据质量需要完整的第二层展示

`part2/contracts/README.md` §7 第 5 条已提出六类展示信息：

1. 七表清洗前/后行数。
2. Q1–Q10 命中数。
3. FP/FN。
4. 召回率与精确率。
5. 单独列出的级联影响。
6. 策略是否冻结。

当前 `HomeView.vue` 仅显示注入/检出列表。`/api/quality/summary` 已返回表行数与召回率，但没有返回 FP/FN、精确率、级联影响、策略状态。因此完整实现需要对既有接口做向后兼容的字段补充，从真实质量元数据读取，缺少的值显示“未提供”。

推荐布局：主页保留质量概况与状态，点击进入可展开的质量明细；明细内提供“表级保留 / 规则对账 / 级联影响”三个分区，六类信息均可直接查看。

### 4.2 Q9 修改后，站点不一定有有效坐标

最新 Q9 策略保留站点、把越界坐标设为 NULL。当前视图模型的 `Number(null)` 会变成 0。接手时需要区分“站点存在”和“坐标可绘制”：

- 地图仅绘制两项坐标均有效的站点，并给出缺坐标站点数。
- 站点选择、排行、营收和订单统计继续保留该站。
- 不补造经纬度、不把缺坐标站点绘制到 `(0, 0)`。

### 4.3 显示所读批次的事实

- API 连通不代表数据刚生成，批次时间与接口状态应分开显示。
- 展示“ML 模型预测 / 基线预测 / 暂无预测”时，读取当前批次 `isBaseline`、`modelVersion` 与结果可用性。
- Q2 政策已变更但尚未重跑的数据，不应被贴上“按最新策略验证通过”的标签。
- 平均等待的 SQL 已修复，旧 ADS 的 0 不会因更新 UI 自动改变。

收尾补充：队友重跑后平均等待仍为 0，原因是生成器的 `reserved_at` 与 `started_at` 相同，属于当前模拟数据特征；不能继续表述为未修复 SQL 缺陷，也不应为了图表好看补造等待值。详见 `part2/scml/warehouse/README.md` 的重跑结论。

## 5. 推荐视觉方向：城市能源指挥舱

主题建议为深石墨蓝底、青绿能源色、少量琥珀告警，采用有明确层级的图表和仪表细节。中心始终是北京充电网络与负荷预测。

| 页面 | 首要问题 | 展示重点 |
|---|---|---|
| 综合主页 | 城市充电网络目前运行如何？ | 关键指标、可交互北京地图、实际/预测负荷、异常与质量概况 |
| 用户视角 | 去哪充、何时充更合适？ | 价格与距离、空闲桩、错峰热力图、可用预测推荐 |
| 充电站视角 | 该站设备与资源如何？ | 站点身份、选择器、设备健康、快慢充结构、日内利用率 |
| 企业视角 | 收益、需求与客户结构如何？ | 时段切换、营收/订单/电量趋势、站点经营排行、RFM |
| 政府视角 | 布局与服务是否均衡？ | 区域覆盖、负荷高峰、利用率差异、减排换算与服务指标 |

避免把所有面板做成同等大小；动画集中在数据刷新、地图选中和趋势切换，优先保证虚拟机流畅与投影可读。DataV 作为已经采用的展示技术保留，通过组件参数和布局形成统一风格。

## 6. 实施顺序与验收

1. **公共视觉与主页样稿**：确定导航、字体、颜色、数值、公共面板与图表主题；用真实 API 做一版可点击主页供视觉评审。
2. **四个视角页**：统一控件和信息层次，逐页优化首屏主线；不移除现有业务分析维度。
3. **数据质量明细与异常状态**：补齐展示字段、缺坐标状态、基线/ML 标识，以及加载/空数据/接口失败保留旧数据的体验。
4. **浏览器验收**：主页在 1920×1080 无横向滚动且主线完整；1366×768 不裁切；地图点击进入正确站点；长站名可读；旧数据与实时接口状态清晰。
5. **回归和交付**：37 项已有 Node 测试、9 条已有页面 E2E、生产构建与相关接口形状检查；增补缺坐标等新增业务行为的测试，保存新的五页截图。

布局重构时保留或同步更新 `.kpi-card`、`.kpi-value`、`.chart`、`__echarts`、DataV 与站点选择器等既有测试定位点。主页保留 ScaleFrame 的内容高度测量；四个视角页继续采用响应式布局。
