# 接口补充：命令容量准入（2026-09-06）

## 批准与范围

用户在上一轮明确建议“完成帧、身份和基础字段检查后，若队列已满，可以直接返回 SERVER_BUSY；成功进入队列的请求，再严格执行原有业务检查顺序”后回复“同意，继续”。本记录据此更新接口合同第 5.1 节，不代替 PM 或队员签字，不操作人工维护的需求矩阵。

这是满负载准入顺序的明确补充，不更改正常业务流程、v1 消息格式、27 个 action、权限、金额、时间戳或业务状态机。仍保留最多 16 个业务连接、256 个待处理命令和唯一 DatabaseWorker；不建立第二套数据库状态镜像，不增加无界验证队列。

## 精确行为

1. 帧、envelope/version、action、身份和基础字段错误仍在容量判定前返回各自错误码；未知 action、匿名/错误角色 reset、无效 confirmation 不得伪装成繁忙。
2. 前置检查通过但命令槽位已满时，返回 `SERVER_BUSY`。不存在的正数 stationId、当前不能重启的设备、类型正确但业务上不完整的预测批次，均等成功准入后再按原业务顺序检查。
3. 容量拒绝不接受业务、不修改数据、不生成持久化业务 ACK、不占用 requestId。调用方保留原 ID 和有效 payload 重试；若此前存在最终 ACK，准入后仍重放原 bytes，容量拒绝不能覆写它。
4. 缓存 health 继续可用；现有业务检查顺序、事务和重复请求保护在准入后不变。可选预测的基础 JSON 类型检查与 `FORECAST_INVALID` 业务语义边界保持区分。

## 与上轮发现的关系

- I1 的合同冲突由本次明确批准解决；需以定向测试和独立评审验证实现对应，而不能仅改文档标绿。
- N1（负数 `horizonH` 错误域）是独立代码回归，不由容量例外豁免。修复必须将完整 signed safe integer 作为纯类型边界，合法类型的 `1..24` 越界仍由业务返回 `FORECAST_INVALID`；非整数/错误类型/超 safe integer 返回 `INVALID_REQUEST`。
- 旧审查记录保留当时判定，当前关闭状态与实际测试结果在后续验证记录中登记；不反向改写历史为“从未发现问题”。
