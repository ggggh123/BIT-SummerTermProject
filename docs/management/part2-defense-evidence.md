## 3. 预判提问与答法

| 可能被问 | 怎么答（都已落在文档里） |
|---|---|
| 「主页新增用户那条线为什么一直是 0？」 | 生成器的 4,985 个用户注册时间**全部早于业务窗口**，窗口内没有注册事件（`ads_meta.newUserNote`）。日活曲线是正常的 900–1,050/天。要么改标题为「窗口内首单新客」，要么让生成器在窗口内注入注册时间重交接 ODS。**不要含糊过去** |
| 「全城峰值负荷 7,153 kW 怎么算的？」 | 那是**最近一天**（2026-09-14 08 时）的全城合计峰值；接口 `/api/gov/peak-load` 按日返回 24 点。窗口内真正最大是 **7,964.665 kW（2026-07-10 18 时）**。两个数都对，口径要写明（备注③） |
| 「KPI 累计订单 97,804，数据质量面板却出现 112,422，哪个对？」 | 两套清洗口径：业务表走 PRL 清洗（97,804 / 7 站 / 251 桩），质量面板的 `rows_before/after` 由 `export_ads_db.py` 的 Python 旁路复算（112,422 / 8 站 / 287 桩）。`ads_meta.cleaningSource` 已标注为过渡口径（备注④） |
| 「R02 重复记录、R04 时间格式各注入 11,200 条却检出 0，是不是漏检？」 | 是**检测规则缺口**，不是数据没问题；合计占注入量 68%。要么补规则，要么声明这两类以 #3 的 PRL 报告为准（`readyForTeamDelivery=false` 待团队冻结） |
| 「小时数据是不是有问题？」 | 确实有 **47 个小时缺口**（expected 15,120 / actual 15,073，`rowOffsetMlSafe=false`）。ML 侧不许直接按行偏移做特征，已先做整点网格对齐再训练（`align_hourly_grid`），见 `part2/ml/MODEL_REPORT.md` §12 |
| 「预测是 MLlib 还是拿昨天的数糊的？」 | 看 `ads_forecast_batch.is_baseline`：`0` 是真实 MLlib 批次，`1` 是 seasonal-naive 基线。大屏与接口都读这个字段，不伪造 |
| 「两个阶段怎么衔接？要不要在 Qt 端加入口？」 | **不用**：`part2-design-review.md` 的 R3 已作废——那是口误，主机浏览器直接打开大屏地址即可 |
| 「分析维度够 8 个吗？对比分析呢？」 | 15 个维度 + 5 组对比，逐条给出「来源表 → 接口 → 页面」，见 `part2-analysis-dimensions.md`；答辩口径建议答**快充 vs 慢充**、**区 vs 区** |
| 「哪些是真实数据、哪些是模拟的？」 | 全部为**项目自生成并标注的模拟数据**；外部参考只有行政区常住人口（第七次人口普查）与碳排因子 0.581 tCO₂/MWh（项目假设），都写在 `ads_meta` 里可 SQL 查证 |
