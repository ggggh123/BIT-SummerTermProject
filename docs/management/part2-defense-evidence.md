## 3. 预判提问与答法

| 可能被问 | 怎么答（都已落在文档里） |
|---|---|
| 「主页新增用户那条线为什么一直是 0？」 | 生成器的 4,985 个用户注册时间**全部早于业务窗口**，窗口内没有注册事件（`ads_meta.newUserNote`）。日活曲线是正常的 900–1,050/天。要么改标题为「窗口内首单新客」，要么让生成器在窗口内注入注册时间重交接 ODS。**不要含糊过去** |
| 「全城峰值负荷 7,153 kW 怎么算的？」 | 那是**最近一天**（2026-09-14 08 时）的全城合计峰值；接口 `/api/gov/peak-load` 按日返回 24 点。窗口内真正最大是 **7,964.665 kW（2026-07-10 18 时）**。两个数都对，口径要写明（备注③） |
| 「KPI 累计订单 97,804，数据质量面板却出现 112,422，哪个对？」 | 两套清洗口径：业务表走 PRL 清洗（97,804 / 7 站 / 251 桩），质量面板的 `rows_before/after` 由 `export_ads_db.py` 的 Python 旁路复算（112,422 / 8 站 / 287 桩）。`ads_meta.cleaningSource` 已标注为过渡口径（备注④） |
| 「R02 重复记录注入 11,200 条却检出 0，是不是漏检？」 | **不是检测漏检，是注入端的 bug，且已定位并修复**：生成器注入重复行时跳过了业务主键 `id`，于是"重复行"主键各不相同，而检测端按契约 `primary_key` 分组，永远命中不到（同时误报 128,817 条）。#2 已在 `feat/part2-02` 拍板口径（按业务主键判重）并同步改生成器与策略文件。**旧批次是修复前生成的故为 0；按 09-15 晚决策已在演示机重跑整链路，新批次转非 0** |
| 「R04 时间格式混杂也检出 0？」 | **已更正并闭环（2026-09-15）**：「检出 0」是旧批次结论。PRL 侧代码早已按契约判定（集成机实跑 **`Q4 TP=11,200 / FP=0 / FN=0`，召回 1.0**），真缺口在 **ADS 侧独立复算**的计数口径（此前仅「不可解析」才计，致大屏恒 0），已修复并补测试（缺陷 D15）。**重跑后报告与大屏均应显示 11,200 / 召回 1.0** |
| 「区政府页的『平均等待』为什么是 0？」 | **是数据特征，不是 bug —— 这是 2026-09-15 重跑后的最终结论**：① **曾有一处技术缺陷**：DWD 时间列是 STRING，Spark 上直接 `UNIX_TIMESTAMP(字符串)` 返回 `null`，相减取平均静默变 0，SQL 已改为显式 `CAST`；② **修完 SQL 后仍是 0，因为生成器压根没建模「预约→开工」的等待时段**——它对 `reserved_at` 与 `started_at` 写入的是**同一个时间戳**（`part2/scml/data_generator/generator.py:486-487`），重跑批次实测 **110,696 / 110,696 条已完成订单两者完全相等**，`ads_etl.sql` 的 `WHERE started > reserved` 又把等值行全部过滤。要让该值非 0 需**改生成器并重跑**（后续批次议题）。**答辩口径：按「生成器未建模等待时段」说明，不要再说成 SQL bug** |
| 「小时数据是不是有问题？」 | 新版批次有 **52 个小时缺口**（expected 17,280 / actual 17,228，`rowOffsetMlSafe=false`）。ML 侧不许直接按行偏移做特征，已先做整点网格对齐再训练（`align_hourly_grid`），训练时网格补齐至 17,280 行，见 `part2/ml/MODEL_REPORT.md` §12 |
| 「预测是 MLlib 还是拿昨天的数糊的？」 | 看 `ads_forecast_batch.is_baseline`：`0` 是真实 MLlib 批次，`1` 是 seasonal-naive 基线。大屏与接口都读这个字段，不伪造 |
| 「两个阶段怎么衔接？要不要在 Qt 端加入口？」 | **不用**：`part2-design-review.md` 的 R3 已作废——那是口误，主机浏览器直接打开大屏地址即可 |
| 「分析维度够 8 个吗？对比分析呢？」 | 15 个维度 + 5 组对比，逐条给出「来源表 → 接口 → 页面」，见 `part2-analysis-dimensions.md`；答辩口径建议答**快充 vs 慢充**、**区 vs 区** |
| 「哪些是真实数据、哪些是模拟的？」 | 全部为**项目自生成并标注的模拟数据**；外部参考只有行政区常住人口（第七次人口普查）与碳排因子 0.581 tCO₂/MWh（项目假设），都写在 `ads_meta` 里可 SQL 查证 |
