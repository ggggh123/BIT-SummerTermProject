> 用法：ADS 产出后，逐行从 ADS 表取真值，与大屏页面显示值对照；不一致则记入缺陷清单并定位（数据问题 / 接口问题 / 展示问题）。

## 抽验方法

1. 从 HDFS 或 `ads.db` 直接查 ADS 表（示例：`hdfs dfs -cat /ev-charging/ads/ads_revenue_overview/*.csv | head`）。
2. 打开大屏对应页面，读取显示值（金额是元，注意 ADS 存的是整数分，需 ÷100 再比）。
3. 差异为 0 记「一致」；否则记录差异值与原因分类。
4. 抽验人与复核人分别签字；本表随答辩材料归档。

### 备注（写进答辩材料的如实说明）

① **电量 0.4 kWh 差异**：`ads_daily` 是逐日四舍五入后再汇总（3,972,087.8），接口与订单口径是直接汇总（3,972,088.2）。金额为整数分所以无差异；比对时不要把 0.4 kWh 当缺陷（分类 D 口径）。

② **在线率 99.3% 偏理想**：故障桩只有 2 个（修复前状态快照几乎全是 `idle`，现已按站点利用率生成 `idle 197 / charging 61 / reserved 27 / fault 2`）。若希望更接近真实运营，需要 #4 调整故障注入比例。

③ **质量检出缺口**：`R02 重复记录` 与 `R04 时间格式混杂` 各注入 11,200 条、**检出 0**，合计占注入量 68%。答辩口径需明确：要么 #3 补齐检测规则，要么声明「ADS 侧口径不含这两类，以 #3 的质量报告为准」。
