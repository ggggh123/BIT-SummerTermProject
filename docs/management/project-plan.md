## 3. 进度登记与补位

- 进度只按可验证证据记录为“已提交、已构建、已测试、已独立运行、已真实联调”之一，不以代码量或提交数代替完成。
- #5 的核心联调测试、服务端或演示补位工作须逐项登记责任、范围、证据和退出条件；不得反向伪造为已完成。
- #1 在每次彩排后把 SHA、执行者、输入黄金库 hash、日志位置、结果和开放缺陷写入每日记录。
- #2 负责服务端归属与评审，#3 负责用户端/腾讯地图并协调本机跨模块集成，#4 负责模拟器/黄金库/运行交付，#5 负责独立回归和换机验证，#1 负责答辩与交付材料。该表是后续责任口径，不冒充队友已经完成这些工作。
- 用户已授权本机介入服务端和数据库；实现来源如实记录，不更改实际人员身份，不替他人签验收。
- 当前共享合并、测试与未闭环事项见 [团队交接单](core-integration-handoff-2026-09-06.md)。

## 5. 范围与分支纪律

- 范围基线见 [scope-baseline.md](scope-baseline.md)，正式调整见 [scope-change-2026-09-04.md](scope-change-2026-09-04.md)。
- 协作路径为 `feat/* -> dev -> main`。各项功能从明确的 dev 提交开展，独立评审后集成；`main` 仅接受经审查的稳定里程碑。最终发布源码必须与实际验收候选一致，合并改变源码时须重新回归。
- Web/ML 使用显式 optional profile 执行其独立验证；不将其依赖、测试、服务或数据新鲜度加入 core gate。
