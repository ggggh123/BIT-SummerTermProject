# 项目计划与 WBS

> 维护人：#1 王浩恩（PM）｜版本：v2｜更新：2026-09-04
>
> 当前主路径遵循 [范围基线 v2](scope-baseline.md)。2026-09-01 五系统计划仍作为历史过程证据保留，不再定义核心发布闸门。

## 1. 主路径与硬闸门

| 阶段 | 核心目标 | 硬闸门 / 责任 |
|---|---|---|
| 立即（审计后） | 服务端 P0 收敛：协议 action、预约—充电—停止—结算状态机、唯一写库和专属测试 | #2 负责；未补齐前为 **NO-GO** |
| 核心集成 | 用户端、服务端、黄金库/模拟器建立可观察的端到端闭环 | #2/#3/#4；每一步记录请求、状态、数据变化和异常路径 |
| 彩排 1 | 从受校验黄金库重置并运行完整核心链路 | 全员；记录提交 SHA、环境、日志和缺陷 |
| 彩排 2 | 在与彩排 1 相同提交上重新复位并重复完整链路 | 全员；两次均无开放 P0、无人工改库、数据一致 |
| 9/10 现场验收 | 仅运行已由双彩排证明的同提交核心脚本与包 | #1/#4；任何 P0 或关键证据缺失均为 NO-GO |

闸门纪律：服务端 P0、核心闭环、数据一致性或双彩排任一未通过，先阻断发布和答辩主线；不得用 Web/ML 的独立成果替代核心证据。

## 3. 进度登记与补位

- 进度只按可验证证据记录为“已提交、已构建、已测试、已独立运行、已真实联调”之一，不以代码量或提交数代替完成。
- #5 的核心联调测试、服务端或演示补位工作须逐项登记责任、范围、证据和退出条件；不得反向伪造为已完成。
- #1 在每次彩排后把 SHA、执行者、输入黄金库 hash、日志位置、结果和开放缺陷写入每日记录。

## 4. 会议节奏

- 每天 09:00 站会（10 分钟）：上一日可验证证据、当日 P0、阻塞与责任人。
- 每天 18:00 集成检查（15 分钟）：核心进程状态、端到端证据、风险状态和是否具备下一步闸门资格。

## 5. 范围与分支纪律

- 范围基线见 [scope-baseline.md](scope-baseline.md)，正式调整见 [scope-change-2026-09-04.md](scope-change-2026-09-04.md)。
- 协作路径为 `feat/* -> dev -> main`。服务端在补齐 P0 并同步当前 `dev` 前不可合入；`main` 仅接受经审查的稳定里程碑。
- Web/ML 使用显式 optional profile 执行其独立验证；不将其依赖、测试、服务或数据新鲜度加入 core gate。
