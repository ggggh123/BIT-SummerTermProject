# 范围变更记录：核心交付重置与可选成果保留

> 编号：SC-2026-09-04｜状态：已确认｜生效：2026-09-04｜最终截止：2026-09-10
>
> 决策人：项目组｜维护人：#1 王浩恩（PM）｜被替代文件：`docs/plans/2026-09-01-ev-charging-platform-design.md` 中“五系统全部作为验收硬门槛”的部分。

## 1. 变更原因

截止时间、当前集成状态和答辩收益重新评估后，项目组决定集中资源完成可运行的用户端—服务端—数据库/模拟器闭环。该决定改变发布门槛和答辩主线，不否定 Web/ML 已完成的工作，也不通过删除兼容接口掩盖范围收缩。

## 2. 变更前后对照

| 项目 | 2026-09-01 历史 v1 | 2026-09-04 当前 v2 |
|---|---|---|
| 核心验收 | Qt 用户端、管理/服务端、SQLite/模拟器、Web、ML 五系统同时通过 | Qt 用户端、管理/服务端、SQLite/模拟器三条核心交付线通过 |
| Web | Web 快照和大屏属于硬门槛 | 可选参考成果；独立测试/演示保留，不影响 GO/NO-GO |
| ML | 训练、预测、发布和 active forecast 属于硬门槛 | 可选参考成果；离线管线/工件/测试保留，无 active forecast 合法 |
| 发布证据 | 历史计划将五系统并列 | 同一提交核心闭环连续两次彩排；P0 为零；不以可选成果替代 |
| 架构入口 | 五系统 HTML 作为历史设计入口 | 新增当前核心架构入口；旧 HTML 作为 2026-09-01 历史基线保留 |

## 3. 精确边界

### 保留

- Qt 用户端的登录、查站/查桩、腾讯地图 Web API 地址解析和 QWebEngineView 驾车/步行导航、预约到结算；地图仍是用户端 P0。
- Qt 管理/服务端的协议、业务校验、状态机、唯一 SQLite writer、统计、远程重启、站点和用户管理。
- SQLite/模拟器的版本化 Schema、固定种子、黄金库及 hash、状态、遥测、故障与复位能力。
- `forecast.publish`、`forecast.latest`、预测表和角色权限、`snapshot_meta`、封存 144 条预测及 manifest/hash，以及 Web/ML 代码、测试、数据、文档和功能分支。

### 取消作为核心硬门槛（不是删除）

- Web snapshot writer、静态 HTTP 服务、Web 真实快照联调与 Web 新鲜度。
- 现场 ML 训练、在线 `forecast.publish`、fresh metrics、active forecast/last-good 预测和真实服务端发布。
- 对 Web/ML 的 Node、科学计算依赖、测试和运行条件作为默认构建、环境检查、smoke、彩排或 release gate 前置条件。

## 4. 影响分析

| 方面 | 影响与处理 |
|---|---|
| 角色 | 五人正式角色不删除。#1 负责范围、答辩和 Web 成果维护；#2 收敛服务端 P0；#3 负责用户端与地图；#4 负责黄金库/模拟器/发布；#5 负责核心联调、服务端或演示补位，并维护 ML 成果。 |
| 接口 | 不删除或重命名 v1 action、字段、状态、错误码。预测与 snapshot 合同改为可选扩展；无 active forecast 必须兼容。 |
| 数据库 | 服务端仍是唯一运行时 writer；保留预测表、静态封存预测和 manifest/hash。基础 core profile 可以没有 active forecast。 |
| 答辩 | 主线展示核心闭环与两次同提交彩排证据；Web/ML 仅作为可选加分演示，并明确其独立验证边界。 |
| 分支 | 路径为 `feat/* -> dev -> main`。保留 `feat/web@1d07976`、`feat/ml@2b1563d` 及其他功能分支，不直接 merge 落后分支；服务端先同步 `dev`、补齐 P0 后再提独立 PR。 |

## 5. 回退与审计

本变更不删除代码、数据、合同、历史文件或远端分支，也不重写共享分支历史。若需撤回，可关闭相关整理 PR 或回退其独立文档提交；历史 v1 和五系统 HTML 保持可访问。任何恢复 Web/ML 为硬依赖的决定必须另行登记范围变更并明确环境、测试、彩排和发布门槛。
