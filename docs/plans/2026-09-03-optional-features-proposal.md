### 1.2 关键约束（额外功能必须遵守）

1. **协议冻结**：27 个 v1 动作已于 9/2 18:00 冻结，之后**只允许向后兼容新增**，不得改名、删除或改含义（主设计 §8）。
2. **功能冻结**：9/8 12:00 后禁止新增功能；9/9 12:00 代码冻结并要求同一提交连续两次彩排通过（主设计 §12）。
3. **红线**：各系统"明确不做"清单（主设计 §4 / 范围基线）不得触碰。
4. **降级规则**：任一闸门未通过时，先砍 P1 表现项，不动摇 9/8–9/10 的冻结与彩排时间（主设计 §12、§15）。

### 1.3 结论

五个系统的**必做范围均有明确边界，且契约、快照和数据模型已提供充足的现成数据**。在不动摇必做范围的前提下，存在若干低风险、高答辩价值的 P1 加分项空间。以下提案全部满足：

- 不触碰任何"明确不做"红线；
- 不破坏已冻结的 27 个动作（仅 F3 涉及一次**向后兼容的只读新增**，需 #2 批准）；
- 数据全部来自已存在的表或快照字段，无新增数据管道；
- 单项工作量控制在 4–8 人时，可在 9/4–9/7 窗口内完成。
