## 1. 当前范围与约束

本表说明交付边界，不宣称某分支功能已经完成。实际完成情况以当次代码、测试、联调和验收记录为准。

## 2. 额外功能候选（F1–F5）

> 全部为 **P1**：核心闸门通过、人员有余力且完成逐项范围确认后才实施；核心受影响时优先取消。以下代码路径是候选实施范围，不表示本次文档更新会修改这些文件。

### F1. 用户端充电过程页增强（含费用预警设想）

| 项目 | 内容 |
|---|---|
| 建议主责 | #1；协作 #3（用户端对接）、#2（计费、停止和结算口径确认） |
| 功能 | 在既有当前订单页上增强站点/桩信息展示，展示服务端返回的累计电量与金额；可增加估算功率曲线、低余额提示，以及结算后的文本电子小票 |
| 数据与口径 | 复用 `order.current`、`user.get` 等已确认字段。累计金额、余额、停止和结算结果均以服务端为准，客户端不自行提交最终费用或改变订单状态 |
| 演示价值 | 让充电中的电量、费用和结算结果更直观；费用预警属于展示增强，不把未验证的自动强停当成既有能力 |
| 改动范围 | `apps/user-client/`；不在本项中隐含服务端状态机变更 |
| 原粗估 | 6–8 人时，需按实际接口与页面基础复核 |
| 验收重点 | 显示金额与服务端一致；提示不冒充真实停止；重复刷新、断线恢复及结算后显示正确；小票注明“模拟结算凭证，非支付凭证” |

具体边界：

- 功率曲线是依据相邻采样的电量差和有效时间间隔计算的**估算功率**，单位换算、订单切换、采样缺失和非正时间间隔必须处理；不能标成真实电表测量值。
- 余额与累计费用的比较仅用于提示。仅凭余额不足或 `INSUFFICIENT_BALANCE` 不能推断服务端已经自动停止充电；该错误码在冻结契约中用于已停止订单的余额不足结算失败。
- “已停止计费，充值后结算”等文字必须有服务端停止结果或 `endedAt` 等权威状态支撑。是否自动强停须由 #2 核对现行规则与实现后确认；需要新增服务端行为时，另行评审，不在此默认授权。
- 原本必做的订单状态、电量、费用和结算闭环不能因 F1 被取消而一起删掉；可裁减的是曲线、预警样式和小票等增强部分。

### F2. 数据库一致性体检报告

| 项目 | 内容 |
|---|---|
| 建议主责 | #4；协作 #2（业务不变量及例外状态确认） |
| 功能 | 只读检查指定 SQLite 数据库，输出终端报告和 JSON 工件，拟放在 `runtime/reports/`；区分 `PASS`、`FAIL`、`SKIP` 和 `NOT_VERIFIED` |
| 核心检查 | 数据库完整性、外键与唯一约束、合法状态枚举、非负余额、活动订单唯一性，以及按冻结状态机定义的订单/桩关联与计费一致性 |
| 可选检查 | 活动预测存在时检查其完整性与合法范围；启用快照诊断时检查版本字段及相应证据。未启用的可选功能不构成核心失败 |
| 数据与口径 | 使用项目已有 Python/SQLite 环境，只读连接及一致读事务，或检查停服后的完整演示库；运行期不写业务库、不修复数据、不成为第二个写入者 |
| 改动范围 | 拟新增 `database/inspect_db.py` 及 `database/tests/` 用例，落在数据模块 |
| 原粗估 | 4–6 人时，需复核规则覆盖与读取方式 |
| 验收重点 | 合法库通过；明确构造的不一致被检出；合法停止未结算、故障及无预测状态不误报；报告记录检查范围与未验证项 |

检查规则必须避免下列误判：

- 金额按冻结契约采用 `qRound64(energyKwh * priceFenPerKwh)`，以分为单位并使用订单的适用单价及服务端累计口径；不能写成任意精度的“电量 × 单价必须零误差”，也不能用当前站点价格机械回算所有历史订单。
- 桩与订单关联必须包含停止未结算、故障、重启等合法状态。`charge.stop` 写入 `endedAt` 后，订单可继续处于 `charging` 直至结算，不能只靠一个状态字段判断是否仍在计费。
- 没有活动预测批次时标为 `SKIP`，而不是 `FAIL`；有活动批次时再按预测契约核验 144 条记录、覆盖范围及取值边界。可选诊断结果与核心检查结论分栏呈现。
- 单个数据库快照只能验证当前版本字段是否合法，不能证明版本随时间单调递增。单调性需要同一运行序列的前后报告或日志证据；证据不足应标为 `NOT_VERIFIED`，演示复位后的新序列不得直接与旧序列比较。

报告用于补充回归与彩排证据，不替代服务端事务测试，也不以“全绿截图”代替检查覆盖说明。

### F3. 模拟器演示导演模式（剧本与可选时间压缩）

| 项目 | 内容 |
|---|---|
| 建议主责 | #4；协作 #1（答辩节奏）、#2（故障与远程重启链路确认） |
| 功能 | 先提供正常运行→故障注入→提示管理员远程重启→确认恢复→继续运行的可控剧本，模拟器日志显示每步说明；高峰档位和时间压缩作为可单独裁减的子项 |
| 演示价值 | 围绕 Qt 用户端、Qt 管理/服务端和模拟器呈现真实故障与恢复链路，与数据库检查报告配套留证；不等待 Web 或 ML 展示 |
| 数据与口径 | 优先复用 `TelemetryEngine`、`telemetry.push`、`simulator.fault_set`；遵守现有时序、幂等及状态机约束，不因剧本需要改写服务端结果 |
| 改动范围 | `simulator/src/core/` 与 `SimulatorWindow.*`，落在数据/模拟器模块 |
| 原粗估 | 4–6 人时；若时间压缩无法在窗口内可靠验证，保留普通速率剧本并删除该子项 |
| 验收重点 | 可开始、暂停和退出；故障、重启结果真实可见；失败有提示；重复运行不造成时间戳倒退、重复计费或绕过业务状态机 |

约束：

- 清除故障标志不等于桩立即恢复空闲。恢复展示须遵守服务端的故障→重启中→恢复流程，不能由模拟器在界面上假造成功。
- 时间压缩不是必做项。若采用，限隔离的、无活动订单的演示场景，不推进正在进行的订单计费；不得依赖 Web 事件流、预测数据或 ML 任务。
- `telemetry.push` 与故障事件共享每桩时序约束，新的事件时间必须严格递增。加速产生未来时间戳后，不能仅切回墙钟继续发包；必须设计保持时序有效的时钟策略，或通过已验证的演示复位开启新场景。
- 存在活动订单时不进入加速场景；加速场景退出后先完成时序与状态检查再允许正常业务演示。若无法保证上述隔离，就不提供时间压缩选项。

### F4. 管理端 request_log 审计日志查看器

| 项目 | 内容 |
|---|---|
| 建议主责 | #5；协作 #2（服务端对接与接口批准）、#4（契约登记复核） |
| 功能 | 管理端增加只读请求日志页，按时间倒序分页展示 requestId、动作、响应码和时间，并支持 requestId 精确查找 |
| 接口候选 | `admin.request_log_list`，拟采用管理员鉴权及 `{requestId?, limit?, offset?}` 载荷；**这是待评审的新增动作名称，不是本文发布后即生效的契约** |
| 演示价值 | 辅助定位失败请求、解释幂等记录及提供过程证据；不声称已有日志覆盖每个操作或每次事务 |
| 数据前提 | 先核查现有 `request_log` 实际字段、记录范围、写入时机和测试；日志缺失或规则尚未落实时，优先解决已确认的核心问题，不把数据“已现成”作为默认前提 |
| 改动范围 | `apps/admin-server/`；若批准新增接口，另行更新 `docs/design/interface-contract.md` 并补充对应测试 |
| 原粗估 | 4–6 人时，接口和数据基础确认后重新评估 |
| 验收重点 | 管理员权限、分页边界、稳定排序、空结果、错误处理；不显示口令、token 等无关敏感字段；不改变原有写入与幂等逻辑 |

开工前须 #2 确认兼容性、字段和访问边界，#4 复核登记。若新增接口无法在冻结前完成评审与验证，就取消本项；不能因其只读而省略测试。

### F5. 系统健康自检面板

| 项目 | 内容 |
|---|---|
| 建议主责 | #5；协作 #2（健康状态及数据来源定义） |
| 功能 | 管理端增加只读健康页，展示服务健康、可确认的模拟器连接/运行状态和检查时间；快照、预测信息放在独立的 optional 诊断区域 |
| 数据与口径 | 首先使用 `system.health` 既有响应及已确认的服务端状态来源；`system.health` 保持冻结字段集合，不为面板直接塞入额外字段 |
| 展示规则 | 区分正常、异常、未验证、未启用及数据过期；模拟器 `running`/`paused` 与连接是否在线分开表达，暂停不能直接解释为断线 |
| 可选诊断 | 只有明确启用对应 optional 功能时，才评估快照版本一致性或预测新鲜度；`forecastRunId: null`、无活动预测或尚无快照不能单独判定核心验收失败 |
| 改动范围 | `apps/admin-server/`；不包含大屏徽章、Web 重建或 ML 开发 |
| 原粗估 | 4–6 人时，缺少状态来源时先缩小展示范围 |
| 验收重点 | 各状态有真实来源；失联、陈旧数据不继续显示正常；可选功能缺席时核心区不误报；面板不代替端到端彩排 |

数据库相关诊断遵守服务端已有线程与数据访问边界，UI 不直接写业务库；如果现有接口无法提供某检查项所需信息，应标为未验证或取消该项，确需新增接口时另行走 #2 的契约评审。快照或预测异常可在 optional 区显示，但不得因此恢复它们的核心发布闸门。

### 3.3 启动条件与裁减规则
