# 核心验收清单

> 版本：2026-09-04 core profile｜适用：9 月 10 日核心 GO/NO-GO
>
> 原则：每个勾选项均须记录同一候选提交 SHA、执行日期/人员、命令或操作、日志/截图位置、结果与缺陷编号。任何 P0 开放、数据矛盾、人工直接改运行库或两次彩排不一致均为 **NO-GO**。

## A. 环境与构建

- [ ] 在 Linux 原生文件系统的干净 build 目录完成 core profile 环境检查；不要求 Node/npm 或 ML 科学计算包。
- [ ] 完整 CMake configure/build 成功，Qt Core/Network/Widgets/WebEngine/Charts/Test 和核心 Python/pytest 依赖可用。
- [ ] 核心 CTest、数据库测试和服务端专属测试均有通过计数；分别记录，不用任一项替代其他项。
- [ ] 启动用户端、管理/服务端和模拟器所需配置已记录，且不含真实腾讯 Key。

## B. 黄金库与数据一致性

- [ ] 从批准的黄金库或基础 core profile 复位，校验 Schema、seed、manifest 与 hash。
- [ ] 记录运行前后用户余额、订单、充电桩状态、遥测、故障和管理统计；它们与操作顺序一致。
- [ ] 未人工直接修改运行时 SQLite 数据库；服务端是唯一运行时 writer。
- [ ] 无 active forecast 时返回/显示合法降级（“暂无预测”），核心找站、导航和充电不受影响。

## C. 用户端与地图

- [ ] 完成 11 位手机号登录或自动注册，并验证会话身份。
- [ ] 查站、查桩、地址解析和排序可用。
- [ ] 腾讯地址解析成功，QWebEngineView 中分别显示驾车和步行路线；外部服务异常时显示真实错误/最后成功路线，不能伪装为实时成功。

## D. 核心业务闭环

- [ ] 用户端发起预约，服务端校验并持久化正确状态。
- [ ] 开始充电后，模拟器状态与遥测按合同进入服务端和数据库。
- [ ] 模拟器故障事件可被服务端处理并在用户端/管理端得到一致的可解释状态。
- [ ] 停止充电并结算后，余额、订单明细、充电桩状态和管理统计一致。

## E. 管理端与模拟器

- [ ] 管理端管理员登录、统计查看、站点/用户管理均通过合同和权限校验。
- [ ] 管理端可执行并验证故障后的充电桩远程重启。
- [ ] 模拟器状态切换、遥测和故障注入均有实际事件证据，而不是仅有单元测试或界面截图。

## F. 断线与双彩排

- [ ] 用户端/网络断线场景有明确降级和恢复结果；不产生重复订单、错误结算或无法解释的状态。
- [ ] 彩排 1：从受校验黄金库开始，在候选 SHA 上走完 A–E；记录全部证据与 P0 清零结论。
- [ ] 彩排 2：重新复位，在**同一 SHA**上重复 A–E；结果与彩排 1 一致。
- [ ] 两次彩排均无开放 P0、无崩溃、无无法解释的数据矛盾后，PM/#4 签署 GO；否则记录 NO-GO 与回退 SHA。

## 可选加分演示（不影响 GO/NO-GO）

- [ ] Web ECharts：可单独展示已验证的 Node 测试、静态 HTTP 200、fixture/fallback；真实快照联调不足须如实说明。
- [ ] ML：可单独展示 12,960→144 离线预测管线、78 passed/3 skipped 和模型工件；未真实服务端发布须如实说明。

以上可选项不构成核心环境、构建、黄金库、端到端、彩排或发布前置条件。
