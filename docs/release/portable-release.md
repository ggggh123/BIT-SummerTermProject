# 三端便携发行包使用说明

本说明对应 Ubuntu x86_64 便携包。实际版本和源码 SHA 见包内 `release.json`，依赖包版本与来源见 `licenses/dependencies.json`；本机验收结果另见对应发行测试记录，不以本文代替兼容性实测。

## 1. 接收方需要什么

- Intel／AMD 64 位 Ubuntu 桌面环境，最低兼容构建目标为 Ubuntu 22.04。
- 正常可用的桌面显示、系统基础库和图形驱动；不是无桌面 Ubuntu Server。
- 用户可读取并执行的解压位置，例如自己的“下载”或主目录。
- 使用腾讯地图时需要网络；登录、站点、充电、订单、管理操作均通过本机服务端完成。

不需要安装 Qt Creator、Qt 开发包、CMake、Ninja、编译器或 Python 开发环境。三端程序、Qt 与启动器运行组件由发行包提供，启动脚本不会重新编译。

按项目负责人要求，当前发行过程只做本机可执行的测试，不下载完整 Ubuntu 安装镜像，不宣称已经在队员的独立 Ubuntu 22.04 虚拟机上实测。

## 2. 解压和启动

先把整个压缩包解压到自己的用户目录，保留内部目录层次。不要只单独复制 `bin` 中的程序。

进入解压目录，右键选择“在终端打开”，执行：

```bash
bash ./启动.sh
```

脚本会创建新的演示运行副本，按顺序启动管理／服务端、模拟器和手机式用户端，并显示结果与日志位置。可以关闭启动终端，关闭三端请使用本包停止脚本。

若 9100 端口已被另一套开发版本占用，可使用其他端口启动：

```bash
bash ./启动.sh --port 19100
```

三个程序会自动使用同一个新端口。脚本不会主动关闭占用端口的其他程序。

虚拟机出现渲染异常时，可以先停止本轮，再尝试软件渲染入口：

```bash
bash ./停止.sh
bash ./启动.sh --software-rendering
```

软件渲染只影响本次应用的环境，不更改系统设置。若仍有地图黑屏，保留本轮日志用于定位，不要反复改动系统 Qt 或升级 glibc。

## 3. 演示账号与充电操作

- 管理员用户名：`admin`；演示密码：`123456`。
- 用户端可使用演示手机号：`13800138000`。

建议按以下顺序演示：

1. 用户端登录，选择站点与可用充电桩。
2. 按页面操作预约并开始充电。
3. 在模拟器窗口点击 `Run`，按钮变为 `Pause` 后开始周期上报。
4. 等待几次上报，观察用户端累计电量、金额与管理端设备状态。
5. 停止充电并结算，查看订单历史和管理统计。

模拟器初始暂停是当前产品行为。“已接入”表示鉴权／快照同步成功，不等于正在生成遥测。用户端大号 `kWh` 是累计电量；若时长增加但电量一直为零，先检查是否点击了模拟器 `Run`。

## 4. 查看状态与停止

```bash
bash ./查看状态.sh
bash ./停止.sh
```

状态结果分别报告进程、服务和模拟器鉴权；不能用“进程存活”代替完整业务验收。停止命令按本轮登记的进程身份退出程序，不按模糊名称批量结束进程。

若普通停止超时，先查看日志和状态。需要强制回收本轮已登记进程时，可以执行：

```bash
bash ./停止.sh --force
```

仍然会核对进程身份；不对身份不符的进程发送信号。

移动解压目录前必须完全停止三端。若运行时误移动了目录，请先移回原位置再停止；不要在运行中删除程序文件。

## 5. 数据保存在哪里

包内 `runtime/golden` 为封存基础数据。实际运行库与日志不写回黄金库，而保存在用户数据目录：

```text
$XDG_DATA_HOME/evcharging/<releaseId>/
```

未设置 `XDG_DATA_HOME` 时，默认位置是用户主目录下的 `.local/share/evcharging/<releaseId>/`。

每轮数据在 `runs/<run-id>/` 中，包括：

- `core-runtime.db`：本轮业务数据库。
- `server.log`、`simulator.log`、`client.log`：各程序输出。
- `manifest.json`：本轮进程身份、启动参数与阶段记录。
- `simulator-status.json`：模拟器的进程／鉴权状态。

每次新启动使用新的演示副本，旧轮次仍保留；它不是默认续接上次业务的生产部署。需要重置当前演示时使用管理端提供的演示复位入口，不要手工覆盖运行中的数据库或删除 `-wal`／`-shm` 文件。

## 6. 腾讯地图默认配置

团队发行包已获授权携带项目负责人的默认腾讯地图 Key，接收方不需要再次填写。该 Key 可从配置中读出，因此这份团队包不应直接公开上传。

默认配置位于包根的 `config.local.ini`。也可以在上述用户数据目录放置自己的同名文件，使用以下结构：

```ini
[tencent]
mapKey=填入自己的腾讯地图Key
```

显式环境变量 `EV_TENCENT_MAP_KEY` 的优先级最高；用户配置覆盖包内配置。不要把真实 Key 发到公开问题单或粘贴进公共日志。

多人使用同一默认 Key 会共享配额。地图提示额度、权限、网络或服务异常时，检查腾讯控制台和网络条件；核心本机业务不依赖地图服务保持在线。不要把第三方服务失败误认为需要重新编译项目。

## 7. 故障反馈

优先提供发行版本、Ubuntu 版本、CPU 架构、完整错误提示及日志路径。可以附相关日志，但发送前检查是否含个人信息或配置值；不要发送 `config.local.ini`。

常见处理：

| 提示／现象 | 建议 |
|---|---|
| 端口已被占用 | 使用 `--port` 指定空闲端口，或按原程序自己的停止方式退出。 |
| 未检测到桌面 | 在 Ubuntu 图形桌面的终端中运行，不用纯 SSH 无显示会话启动。 |
| 已有活跃或身份不明的轮次 | 先执行本包状态／停止命令；不要反复启动。 |
| 程序指纹不符或资源缺失 | 重新校验压缩包并完整解压，避免混用不同版本的 `bin` 和 `lib`。 |
| 权限拒绝 | 换到允许执行的用户目录重新解压；不要用 root 启动 Qt WebEngine。 |
| 地图未显示 | 先查日志、网络和配额，必要时尝试软件渲染；不要盲目更换系统库。 |
| 电量没有增长 | 检查模拟器是否点击 `Run`，然后核对充电状态与上报日志。 |

包内 `licenses` 保存第三方许可与来源；分发时应与程序一起保留。
