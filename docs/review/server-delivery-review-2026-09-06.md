## 尚需用户决定的合同边界

冻结接口合同 §5 不仅要求身份/纯参数先于容量，还要求数据库业务检查先于 `SERVER_BUSY`。唯一数据库线程被锁等待阻塞、已有 256 条待处理命令时，当前架构无法同时做到立即查询权威实体/状态、保持容量上限、前台不执行 SQL。

因此不擅自将身份和纯参数的修补描述为完整合同符合。已向用户提出的建议是：完成帧、身份和纯参数检查后，队列已满可返回 `SERVER_BUSY`；只有成功准入的请求才继续权威数据库业务检查。**建议尚未获批准，合同未改。** 若保持原文，则需另行规划严格满足的准入/权威读模型方案；不能通过无界排队、跨线程查询或陈旧业务快照暗中绕过。
