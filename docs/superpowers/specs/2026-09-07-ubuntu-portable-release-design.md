# Ubuntu 22.04 起步的三端便携发行包设计

日期：2026-09-07。

状态：用户已批准书面设计并要求继续执行。执行中新增约束：不下载完整 Ubuntu 22.04 镜像，只做本机能够执行的测试；已取得约 29 MB Ubuntu Base 仅用于本机兼容构建，不再另建独立验收系统。本文不是发行验收报告，也不表示发行包已经生成。

## 1. 目标与已确认范围

为当前充电平台制作免编译、免安装 Qt 的便携软件包，让队员在 Intel／AMD x86_64 Ubuntu 桌面虚拟机上解压后启动三端。最低兼容目标为 Ubuntu 22.04；另在本机 Ubuntu 25.04 上回归，不把未测的所有更高版本统称为已验证。

发行基线为当前 `core-integration` 工作树，设计时源码提交为 `3aa9a2721d493584a40640d9a0147d802d9723e6`。实际发行清单必须记录最终构建使用的源码版本，以及必要的发行适配变更，不能只沿用这个历史编号。

交付必须包含：

- 用户客户端、管理／服务端、设备模拟器三个 Release 程序。
- 程序所需的 Qt、WebEngine、插件与非系统基础依赖。
- 启动器所需的 Python 解释器、标准库及其必要扩展，避免要求接收方自行安装工具。
- 封存核心黄金库、校验文件、必要数据库结构与运行支持文件。
- 可迁移的启动、停止、状态检查入口，以及中文说明、版本清单和校验文件。
- 用户已授权随包携带的腾讯地图默认 Key；允许接收方更换配置。
- 第三方许可证、来源与版本信息。

不包含：Web 大屏和 ML 的重新集成、业务重构、新的 UI 主题、队员源码编译环境的全面修复、ARM 包、无桌面 Server 支持、自动更新器或 `.deb` 安装器。

不触碰人工维护的需求矩阵，不清理已有工作树、运行库或历史成果，不自动推送远端。

## 2. 方案选择与兼容依据

选择 `tar.gz` 便携包，不以系统安装包作为首轮交付。便携包便于传递、替换和排错；`.deb` 的安装／卸载与系统依赖管理留作后续独立需求。首轮也不增加 AppImage 封装层。

本机核对结果：Ubuntu 25.04、glibc 2.41、Qt 6.8.3；已安装的 Qt WebEngine Core 依赖 `GLIBC_2.38`。Ubuntu 22.04 的 glibc 为 2.35，因此不能把本机这一套 Qt 运行库直接复制过去作为兼容方案。[Ubuntu 官方 libc6 信息](https://packages.ubuntu.com/jammy/libc6)

使用本机已准备的精简 Ubuntu 22.04 amd64 用户空间构建，保持现有全局开发环境不变；不下载完整安装镜像，不建立另一套验收系统。测试在本机进行，构建依赖不进入接收方系统。不得通过替换目标系统 glibc 来取得表面兼容。

优先采用 Ubuntu 22.04 可获得的 Qt 6.2.4 模块，项目 CMake 声明的下限也是 Qt 6.2。若发现较新 API 使用，先评估保持行为不变的局部兼容写法并运行对应回归；若必须采用较新 Qt，其构建也必须保持 22.04 ABI 底线，并在版本清单中记录，不能悄悄提高最低系统要求。[Ubuntu 官方 Qt WebEngine 开发包信息](https://packages.ubuntu.com/jammy/qt6-webengine-dev)

使用发行版提供的预编译 Qt 依赖，不默认从源码重编 Chromium／Qt WebEngine。应用构建使用 Release，构建缓存保存在独立构建区；发行包不携带 CMake 缓存、测试二进制或调试符号大文件。

## 3. 发行包布局

下面为约定布局；`release-id` 由版本号、构建日期和源码短 SHA 组成，在生成时固定。

```text
EVCharging-<release-id>-ubuntu22.04-x86_64/
├── 启动.sh                        不编译，初始化本轮数据并启动三端
├── 停止.sh                        按记录停止当前发行版进程
├── 查看状态.sh                    显示进程、服务和日志位置
├── 使用说明.md                    首次运行、账号、模拟器操作和排错
├── release.json                   版本、平台、依赖及程序指纹
├── SHA256SUMS                     不可变发行内容的校验清单
├── config.local.ini               默认连接参数与真实地图 Key
├── bin/                           三端程序
├── lib/                           私有运行库
├── plugins/                       Qt 平台、SQL、图像、TLS 等插件
├── libexec/                       QtWebEngineProcess
├── resources/                     WebEngine 数据资源
├── translations/                  WebEngine locales 与所需 Qt 翻译
├── fonts/                         可再分发的中文字体及授权说明
├── python/                        私有 Python 解释器和标准库
├── support/                       发行启动器及共享运行支持代码
├── database/                      schema.sql 与所需数据复制支持
├── runtime/golden/                core.db、校验值及清单
└── licenses/                      第三方许可、版权与来源
```

外部交付为上述目录的压缩包及独立的压缩包 SHA-256 文件。包名和校验值以真正生成的结果为准，设计文档不预报包体积或构建成功。

所有运行路径从发行入口自身定位，不出现对本机用户名、共享文件夹、旧构建目录的依赖。支持用户有读取和执行权限的解压目录，包括路径含空格和中文的情况；无执行权限的挂载点应给出明确提示，不能靠 sudo 启动绕过。

## 4. 启动器与运行状态

保留现有本机开发启动器，新增发行适配层。复用 `scripts/demo_runtime.py`、`demo_processes.py`、`demo_protocol.py` 和数据复制逻辑中的有效机制，避免重新实现业务协议。

发行适配必须解除以下开发期依赖：

- 不执行 CMake、Ninja、Make、编译器或 Git。
- 不读取 `CMakeCache.txt` 证明程序归属，改为读取 `release.json` 并校验包内程序指纹。
- 不依赖固定源码路径查找 SQL、黄金库或配置。
- 不要求队员手动设置模拟器认证环境变量；启动器为本轮生成共享认证值，仅传递给相关进程。

启动顺序：检查平台和桌面条件 → 加载配置并检查端口／包完整性 → 创建独占运行副本 → 启动管理服务 → 协议健康检查 → 启动模拟器并确认鉴权 → 启动用户端 → 输出状态、日志位置和操作提示。

启动检查应区分图形进程存活、服务可用、模拟器已鉴权和遥测正在运行，不把三者合并成一个“全部业务正常”。

本轮不改变模拟器默认暂停的业务行为。启动完成后明确提示点击模拟器 `Run` 开始上报，并在中文说明中给出充电演示顺序；“开箱即用”指无需配置开发环境，不表示替用户自动执行充电业务。充电电量增长仍作为验收项。

可变运行数据放在用户数据目录中，优先遵循 `XDG_DATA_HOME`，默认在 `~/.local/share/evcharging/` 下按发行 ID 分组；日志与当前轮次指针同样不写回安装内容。包内默认配置可被该用户目录的本地配置覆盖，显式环境变量优先级最高。

每次开始新演示生成独立运行副本，不覆盖上一轮，也不修改黄金库。停止后移动发行目录仍应能够再次启动；历史日志和数据库保留。运行期间不支持移动或删除发行目录。历史记录校验采用发行身份与实际进程身份，不能让旧源码绝对路径阻止重新启动。

保留文件锁、防重复启动、端口占用检查、原子状态写入，以及 PID／启动时间／可执行路径／boot ID 身份核对。停止只针对本轮记录的进程，不使用模糊名称批量杀进程。启动失败时回收本次已登记进程并保留日志；清理旧数据不属于自动启动操作。

## 5. 依赖收集、显示与地图

动态部署时，Qt 运行库与插件必须位于一致的私有目录，使用局部环境和必要的相对路径配置定位。不得修改全局 `LD_LIBRARY_PATH`、系统库或 shell 登录配置。[Qt 官方 Linux 部署说明](https://doc.qt.io/qt-6/linux-deployment.html)

除直接链接库外，还需检查动态加载项：Qt xcb 平台及其依赖、SQLite 插件、图像插件、TLS 支持、WebEngine 子进程、资源包与 locales。按实际 Qt 构建产物收集资源，不假定每个版本使用相同清单。[Qt 官方 WebEngine 部署说明](https://doc.qt.io/qt-6/qtwebengine-deploying.html)

系统边界为正常 Ubuntu 桌面提供的内核、glibc、图形会话与驱动接口；其余应用依赖尽可能随包封装。不能声称在没有桌面或显卡栈的任意最小系统上也能运行。

默认使用稳定的桌面平台配置，至少验证 Ubuntu 桌面的 X11／XWayland 路径。提供作用于本次程序的虚拟机软件渲染兼容入口，用于黑屏或 GPU 初始化问题；不把关闭 WebEngine 安全沙箱当常规默认修复。中文字体须随包或具有可验证的降级显示方案，不能在队友机器上变成方框。

默认地图 Key 只在本地打包阶段注入最终配置，不写入源码、设计文档、测试快照或公开 CI 日志。打包脚本只能接收密钥输入位置，不在命令行中硬编码真实值。最终团队分发包包含 Key 是用户明确授权的结果，不能当作公开发布包直接上传公共下载页。

配置完整性应允许用户正常更换 Key，不因修改可变配置触发不可变程序校验失败。校验工具不得打印密钥值。队员共享默认 Key 的额度；腾讯地图仍需要网络、权限与有效配额。导航失败不应阻止非地图核心业务启动。

预计新增仓库内发行构建／收集／启动支持、对应测试和中文说明。只有实际编译或运行验证证明必要时，才对现有程序做局部兼容、资源定位或启动适配；不重写订单、计费、协议、数据库业务字段或既有 UI。

本机已有 README 与目录说明变更保持独立，不夹带入仅针对发行设计的提交。打包采用显式文件白名单，不能把工作区整体压缩，也不能夹带旧运行库、配置备份、Git 内部数据或开发工具缓存。

第三方依赖按实际版本保存许可证与版权说明，并满足相应源码获取／再分发条件。若某依赖许可不允许拟定再分发方式，必须先调整依赖或交付方式，不能省略许可问题后宣布完成。

## 7. 验收标准

| 验收项 | 合格条件 |
|---|---|
| 来源与可追溯性 | 清单记录实际源码 SHA、补丁／脏状态处理、构建系统、编译器、Qt 与依赖版本，程序指纹和压缩包校验值吻合。 |
| Ubuntu 22.04 ABI | 所有应用及随包 ELF 依赖符合目标平台，不引用构建目录或本机较新的系统库；动态加载插件也检查。 |
| 免开发工具 | 在本机从解压包运行，通过受控环境、依赖路径检查和启动记录确认不调用开发工具、不加载宿主 Qt；不能将其描述为全新 22.04 系统验证。 |
| 三端界面 | 管理登录、管理首页、手机式用户界面、模拟器均可见；中文无缺字，主题和资源没有明显丢失。 |
| 腾讯地图 | 用包内默认配置真实验证地址解析及至少一次路线加载；网络／权限／额度失败单独记录，不用替身测试冒充。 |
| 充电闭环 | 登录、查站、开始充电、手动 Run 上报、电量增长、停止、结算和订单历史可验证。 |
| 数据与复位 | 黄金库校验通过，运行使用独立副本；在线复位可用；旧轮次不被覆盖。 |
| 路径迁移 | 普通、空格及中文路径均验证；完全停止后移动目录，再启动不依赖原路径。 |
| 生命周期 | 重复启动、端口占用、进程提前退出、停止和再次启动均有明确结果，不误停其他进程。 |
| 离线情况 | 不请求腾讯地图时核心本机业务可运行；断网地图错误可解释且不阻塞其他页面。 |
| 本机回归 | 同一发行包在本机 Ubuntu 25.04 上验证；不以本机成功替代 22.04 验证。 |
| 分发内容 | 不含源码构建缓存、历史运行数据或额外凭据；用户授权的默认 Key 存在但不出现在日志中；许可齐备。 |

验收证据应记录具体环境、命令、结果和界面截图。22.04 用户空间容器／chroot 可用于构建和 ABI 检查；若共享宿主内核或图形会话，必须明确写出，不将其冒充独立完整虚拟机验收。未取得的验证项标为未验证，不标为通过。

不得通过默认禁用故障分支、跳过失败测试或隐藏缺失依赖取得“开箱即用”结论。完整发行是否完成，以最终包的测试结果判断，不以源码构建成功判断。
