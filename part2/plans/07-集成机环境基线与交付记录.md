## 7. 日常运维

### 7.1 Hadoop 启停（虚拟机重启后必须手动执行）

```bash
sudo -u hadoop bash -lc "start-dfs.sh && start-yarn.sh"   # 启动
```

### 7.4 网络与 IP

- 当前为 VMware NAT，Windows 宿主可直接访问；若需**其他成员机**访问，需改为桥接模式。
- **名称解析（2026-09-15 已统一，见本文 §2 说明与《10》§3）**：`/etc/hosts` 实为 `127.0.0.1 localhost niyujun01`，即 **`niyujun01` 解析到回环地址**（`hostname -f` 亦为 `localhost`），**不再是**此前记录的 `192.168.59.128 niyujun01`。
  - **收益**：`hdfs://niyujun01:8020` 与 `hdfs://localhost:8020` 完全等价；且 **DHCP 更换 IP 不会导致 HDFS 失联**，本文件无需再随 IP 维护。
  - **代价**：NameNode RPC `8020`、ResourceManager RPC `8032` **仅监听回环**，宿主机与其他成员机**无法直连 HDFS/YARN 的 RPC 端口**。Web UI（NameNode `9870`、YARN `8088`）与 Flask `5000` 监听 `0.0.0.0`，外部正常可达。
  - **对本项目无影响**：Flask 读虚拟机**本地**的 `ads.db`，Spark 作业全部在虚拟机内运行，不跨机访问 HDFS。
- 可用宿主机命令自动查 IP：
  ```powershell
  & "D:\虚拟机\vmrun.exe" -T ws getGuestIPAddress "C:\Users\12721\Desktop\资源\Ubuntu2204Bit\BitDev.vmx"
  ```

### 9.3 一键脚本合并结果

统一入口：`scripts/part2/30-start-demo.sh` / `31-stop-demo.sh`（原 `part2/scripts/start_part2.sh`、`stop_part2.sh` 已删除）。

合并后同时适配两种部署形态，并修正了一个隐蔽缺陷：

| 缺陷 | 现象 | 修正 |
|---|---|---|
| `jps` 枚举不到守护进程 | 集成机上 Hadoop 以 `hadoop` 用户运行，`bit` 的 `jps` 看不到；`sudo -u hadoop jps` 也报"找不到命令"（非 login shell 的 PATH 不含 JDK） | 统一用 `sudo -u hadoop bash -lc "jps"`，并自动探测应使用哪种模式 |
| **信任启动脚本退出码导致误报成功** | 以无权限用户运行 `start-dfs.sh` **返回 0 却不启动任何进程**，脚本误报"HDFS 已启动"，实际守护进程 2/5 | 改为**以"守护进程是否真的出现/消失"为成功判据**（轮询最多 30 秒） |

**实测**：全停（Flask + YARN + HDFS 全部干净退出）→ 一键启动 → `守护进程: 5/5（jps 模式: sudo）`，Flask 就绪，访问地址正常输出。
