## 6. 环境基线统一与双轨支持（2026-09-15 第二轮）

### 7.1 背景：审计发现的基线冲突

另一侧审计指出：`part2/plans/06`、`02` 冻结的是 **JDK 17 + Hadoop 3.4.1 + Spark 3.5.7**，但仓库内运行时脚本的默认值仍是 **JDK 8 + Hadoop 3.2.1 + 自建 CPython 3.10.21**（#3 那台机器的组合）。集成机之所以能跑，是因为 `/usr/local/ev-part2/` 下放了三个**未入库**的手工适配文件——这正是「文件与环境不一致」的根源。

处置：**把仓库脚本的默认值改为团队冻结基线，并保留完整覆盖能力**（#3 的旧环境不受影响）。

### 7.2 改造清单（7 个文件）

| 文件 | 改动 |
|---|---|
| `part2/scripts/ev-part2-env.sh` | 默认值改为基线；**全部变量改为 `${VAR:-默认}`** 以支持覆盖；JDK/Python 三级解析（显式变量 → 标准位置 → PATH 反查）；`HADOOP_CONF_DIR` 改为「**确认 core-site.xml 存在**才接管」（避免空目录误判）；新增 `EV_PART2_HDFS_USER` 自动探测（HDFS 客户端身份） |
| `part2/scripts/ev-part2` | 支持 `EV_PART2_TOOLCHAIN` 迁移整套运行时（原来硬编码 `/usr/local/ev-part2`）；help 显示当前工具链 |
| `part2/scripts/cluster.sh` | **双形态自适应**：`system`（系统级 Hadoop，`start-dfs.sh`，支持 `EV_PART2_HADOOP_USER` 经 `sudo -n -u` 代执行）/ `local`（专用目录 `--daemon`，保留原逻辑）；判活统一为「进程真实数量 + 端口」；`stop` 增加残留进程兜底清理 |
| `part2/scripts/configure_local.py` | 去除全部版本硬编码（JDK/Python/YARN 内存/路径均来自环境变量）；**补齐 JDK 17 必需的 `--add-opens`**（hadoop-env/yarn-env）；YARN 内存按物理内存自动取值（可用 `EV_PART2_YARN_MEMORY_MB` 覆盖）；新增 `EV_PART2_CONFIG_MIGRATE=1` 迁移开关（旧配置先备份再覆盖） |
| `part2/scripts/check_env.py` | 期望值默认取基线且**全部可参数化**（`--expect-*` / `EV_PART2_EXPECT_*`）；`scope` 与 `ubuntu22_verified` **按实际 OS 动态生成**；守护进程检查支持跨用户（`sudo -n -u $EV_PART2_HADOOP_USER jps`） |

| `part2/scripts/install_global_runtime.sh` | 文件头标注「**旧基线专用**（JDK 8 + Hadoop 3.2.1），冻结基线机器勿执行」；目标保护列表扩展为包含 `/usr/local/jdk-17`、`/usr/local/hadoop-3.4.1`、`/usr/local/bin/python3`、`/etc/profile.d/hadoop-env.sh`，防止误把基线机器指向旧版 |
